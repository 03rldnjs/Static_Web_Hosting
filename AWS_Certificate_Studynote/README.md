## 2. Development History

본 프로젝트는 처음부터 완성된 형태로 제작한 것이 아니라, 기본적인 HTML 문서에서 출발하여 실제 사용 과정에서 발견한 불편함을 하나씩 개선하는 방식으로 발전시켰습니다.

### Phase 1. Initial Version — 기본 학습 노트 제작

초기 버전은 AWS 학습 내용을 웹 브라우저에서 읽을 수 있도록 하나의 HTML 파일에 정리하는 것을 목표로 제작했습니다.

**주요 구현 내용**

- HTML을 활용하여 학습 노트의 기본 구조 작성
- CSS를 HTML 내부에 작성하여 전체적인 디자인 구성
- AWS 공식 문서와 강의 내용을 바탕으로 학습 자료 정리
- AWS CLF-C02 시험의 4개 도메인과 출제 비중 표시
- 글로벌 인프라, IAM, EC2 등 주제별 학습 내용 구성
- 목차와 앵커 링크를 활용한 페이지 내 이동 기능 구현

**디자인 및 레이아웃**

- AWS를 상징하는 오렌지 계열 색상을 중심으로 디자인
- 본문과 제목의 크기, 여백, 색상을 조정하여 가독성 확보
- CSS Grid를 활용하여 목차와 본문을 나누는 2단 레이아웃 구성
- 화면 너비에 따라 레이아웃이 변경되는 반응형 디자인 적용
- 학습 내용의 중요도와 시험 도메인을 색상으로 구분

초기 버전은 별도의 JavaScript 없이 HTML과 CSS만으로 구성했습니다. 하나의 파일에서 모든 내용을 관리할 수 있어 제작과 수정이 간단했지만, 기능이 늘어날수록 코드의 길이가 길어지고 유지보수가 어려워질 수 있다는 한계가 있었습니다.

### Phase 2. Search Feature — 학습 내용 검색 기능 추가

학습 자료가 늘어나면서 원하는 내용을 목차에서 직접 찾는 과정이 번거로워졌습니다. 이를 해결하기 위해 JavaScript를 활용한 검색 기능을 구현했습니다.

**주요 구현 내용**

- 별도의 `search.js` 파일을 생성하여 검색 로직 구현
- HTML 페이지에 검색창과 검색 결과 영역 추가
- 각 학습 섹션의 제목과 본문을 대상으로 검색 수행
- 여러 개의 검색어를 입력하면 모든 검색어가 포함된 항목을 찾는 AND 검색 구현
- 검색 결과의 개수 표시
- 검색 결과에 해당하는 본문 일부를 미리 볼 수 있는 스니펫 제공
- 검색 결과를 클릭하면 해당 학습 섹션으로 이동
- ESC 키를 누르면 검색어와 검색 결과 초기화

검색 기능을 별도의 JavaScript 파일로 분리하여 구현함으로써 HTML 문서의 구조와 검색 로직을 독립적으로 관리할 수 있도록 했습니다.

### Phase 3. UI Improvement — 사용자 인터페이스 개선

검색 기능을 비롯한 새로운 요소가 추가되면서 기존 디자인과 자연스럽게 어울리도록 사용자 인터페이스를 개선했습니다.

**주요 작업**

- 검색창과 검색 결과 영역의 디자인 조정
- Font Awesome 6.7.2 CDN 연결
- 검색창에 돋보기 아이콘 적용
- 검색 기능을 보다 직관적으로 사용할 수 있도록 시각적 요소 보완

기존의 텍스트 중심 인터페이스에 아이콘을 추가하여 사용자가 기능을 쉽게 인식할 수 있도록 개선했습니다.

### Phase 4. Sidebar Toggle — 사이드바 접기 및 펼치기 기능 추가

학습 콘텐츠가 늘어나면서 본문을 확인할 때 사이드바가 차지하는 공간이 불필요하게 느껴지는 경우가 있었습니다. 이를 개선하기 위해 JavaScript를 활용하여 사이드바를 접거나 펼칠 수 있는 기능을 추가했습니다.

**주요 구현 내용**

- 사이드바에 접기 및 펼치기 버튼 추가
- 버튼 클릭 시 사이드바의 표시 상태 변경
- CSS Class를 활용하여 사이드바의 레이아웃 동적 변경
- 사이드바가 접힌 상태에서도 본문 영역을 유지하도록 구성
- HTML, CSS, JavaScript를 연동하여 사용자 인터랙션 구현

기존에는 항상 표시되던 사이드바를 사용자가 직접 제어할 수 있도록 개선했습니다. 이를 통해 학습 내용을 확인할 때 본문에 더 집중할 수 있는 환경을 마련했습니다.

### Phase 5. Sidebar UI Refinement — 사이드바 버튼 디자인 및 위치 개선

최초 구현된 사이드바 접기 및 펼치기 기능을 실제로 사용하면서 버튼의 위치와 디자인을 개선할 필요성을 확인했습니다. 기존에는 버튼이 한글 텍스트로 표시되어 있었으며, 목차와의 배치도 직관적이지 않았습니다.

**주요 구현 내용**

- 사이드바 접기 및 펼치기 버튼을 목차 상단에 배치
- 한글 텍스트 대신 방향을 나타내는 화살표 아이콘 적용
- 목차의 접힘 및 펼침 상태에 따라 아이콘 방향 변경
- SVG를 활용하여 버튼 아이콘 구현
- JavaScript를 통해 버튼 클릭 시 아이콘과 사이드바 상태를 함께 변경
- 버튼의 `aria-label`, `aria-expanded`, `title` 속성을 활용하여 접근성 개선

기존의 기능을 유지하면서 버튼의 위치와 시각적 표현을 개선했습니다. 특히 SVG 아이콘을 활용하여 사용자가 사이드바의 현재 상태와 버튼의 기능을 직관적으로 파악할 수 있도록 했습니다.

### Phase 6. Home Dashboard & Page Navigation — 메인 대시보드 및 페이지 전환 기능 구현

기존 웹 페이지는 접속하면 모든 학습 내용이 하나의 긴 페이지에 연속적으로 표시되는 구조였습니다. 학습 자료가 지속적으로 늘어나면서 원하는 주제를 찾기 어려워졌고, 프로젝트의 전체적인 구성을 한눈에 파악할 수 있는 시작 화면의 필요성을 느꼈습니다.

이를 해결하기 위해 기존 학습 페이지와 별도로 Home 대시보드를 구성하고, 사용자가 원하는 학습 영역으로 이동할 수 있도록 페이지 전환 기능을 구현했습니다.

**주요 구현 내용**

- 기존 학습 페이지와 별도로 Home 대시보드 구성
- 프로젝트 소개 및 AWS CLF-C02 시험 개요 표시
- CLF-C02 시험의 4개 도메인을 카드 형태로 시각화
- Advanced Topics를 별도의 카드로 구성하여 심화 학습 영역 제공
- 도메인 카드를 클릭하면 해당 학습 페이지로 이동하도록 구현
- Home 버튼을 추가하여 학습 페이지에서 메인 대시보드로 돌아갈 수 있도록 구성
- JavaScript를 활용하여 Home과 Study 페이지의 표시 상태를 동적으로 변경
- CSS의 `hidden` 속성을 활용하여 페이지 전환 시 불필요한 콘텐츠를 숨기도록 구현
- 기존 사이드바, 검색 기능 등 기존 기능과 페이지 전환 기능의 연동

기존의 긴 단일 학습 페이지를 Home과 Study 영역으로 구분하여 웹 사이트의 전체적인 구조를 개선했습니다. 사용자가 처음 접속했을 때 프로젝트의 목적과 학습 영역을 직관적으로 파악할 수 있으며, 원하는 도메인을 선택하여 학습을 시작할 수 있도록 구성했습니다.

### Phase 7. Domain-Based Content Filtering — 도메인별 학습 콘텐츠 필터링 구현

Phase 6에서 Home 대시보드와 페이지 전환 기능을 구현했지만, 도메인 카드를 클릭하더라도 기존 학습 페이지의 모든 콘텐츠가 표시되는 문제가 있었습니다. 사용자가 선택한 도메인과 관계없는 학습 내용까지 함께 노출되기 때문에 도메인별로 학습 자료를 구분할 필요가 있었습니다.

이를 해결하기 위해 각 학습 섹션에 도메인 정보를 부여하고, 사용자가 선택한 도메인에 해당하는 콘텐츠만 표시하도록 필터링 기능을 구현했습니다.

**주요 구현 내용**

- 각 학습 섹션에 `data-domain` 속성을 추가하여 CLF-C02 시험 도메인 정보 지정
- 기본 학습 내용과 심화 학습 내용을 구분하기 위해 `data-level` 속성 추가
- JavaScript를 활용하여 선택한 도메인에 해당하는 학습 섹션만 표시하도록 구현
- 선택한 도메인에 해당하지 않는 학습 섹션은 `hidden` 속성을 활용하여 숨김 처리
- 학습 콘텐츠의 표시 여부에 따라 사이드바 목차도 함께 필터링
- 해당 도메인에 표시할 학습 내용이 없는 경우 사이드바의 목차 제목과 목록을 숨기도록 구현
- 여러 도메인의 학습 내용이 함께 포함된 그룹에서는 현재 선택한 도메인에 해당하는 콘텐츠가 존재하는 경우에만 그룹 제목 표시
- Advanced Topics 선택 시 특정 도메인에 종속되지 않고 모든 심화 학습 콘텐츠를 모아서 표시하도록 구현
- 검색 결과 클릭 시 해당 콘텐츠가 속한 도메인 또는 Advanced Topics 화면으로 자동 전환되도록 기존 검색 기능과 연동

기존에는 학습 페이지 전체에 모든 내용이 표시되었지만, 이번 개선을 통해 사용자가 선택한 도메인에 해당하는 자료만 확인할 수 있도록 변경했습니다. 또한 본문뿐만 아니라 사이드바 목차에도 동일한 필터링 로직을 적용하여 화면에 표시되는 학습 내용과 목차가 일치하도록 구성했습니다.

특히 `data-domain`과 `data-level` 속성을 활용하여 학습 콘텐츠의 분류 정보를 HTML에서 관리하고, JavaScript가 해당 정보를 바탕으로 콘텐츠를 동적으로 표시하도록 구현했습니다. 이를 통해 앞으로 새로운 학습 내용을 추가하더라도 해당 속성만 지정하면 기존 필터링 기능에 자연스럽게 반영될 수 있도록 확장성을 고려했습니다.


### Phase 8. Global Search — 전체 학습 콘텐츠 통합 검색 기능 구현

Phase 7에서 도메인별 학습 콘텐츠 필터링 기능을 구현했지만, 기존 검색 기능은 Study 페이지 내부에만 존재했습니다. 따라서 사용자가 특정 AWS 서비스나 개념을 검색하려면 먼저 원하는 도메인을 선택한 후 검색 기능을 이용해야 했습니다. 또한 기본 학습 내용과 심화 학습 내용을 함께 검색하려면 각 학습 영역을 직접 이동해야 하는 불편함이 있었습니다.

이를 개선하기 위해 Home 화면에서도 전체 학습 콘텐츠를 검색할 수 있도록 통합 검색 기능을 구현했습니다. 기존 Study 페이지의 검색 기능을 유지하면서 Home과 Study 페이지의 검색창이 동일한 학습 데이터를 대상으로 검색하도록 구성했습니다.

**주요 구현 내용**

- Home 화면의 소개 영역 아래에 전체 학습 콘텐츠를 검색할 수 있는 통합 검색창 추가
- 기존 Study 페이지의 검색 기능과 Home 화면의 검색 기능이 동일한 검색 데이터를 사용하도록 `search.js` 구조 개선
- `data-domain`과 `data-level` 속성을 활용하여 기본 학습 내용과 Advanced Topics를 포함한 전체 60개 학습 섹션을 검색 대상으로 설정
- 각 학습 섹션의 제목, 본문, 도메인 및 학습 수준 정보를 수집하여 검색 데이터 구성
- 검색어를 소문자로 변환하고 공백을 기준으로 분리하여 여러 검색어가 입력된 경우에도 모든 검색어가 포함된 콘텐츠만 검색 결과로 출력하도록 구현
- 검색어가 제목에 포함된 학습 콘텐츠를 우선적으로 표시하여 검색 결과의 탐색 편의성 개선
- 검색 결과에 학습 주제의 제목뿐만 아니라 소속 도메인과 학습 수준을 함께 표시하도록 구현
- 검색어가 포함된 본문 일부를 미리보기 형태로 제공하고 전체 검색 결과 개수를 표시하도록 구현
- 검색 결과가 없는 경우 별도의 안내 메시지를 출력하도록 구성
- Home 화면에서 검색 결과 클릭 시 해당 콘텐츠의 `data-domain`과 `data-level` 정보를 확인하여 선택한 도메인 또는 Advanced Topics 화면으로 자동 전환되도록 구현
- 기존 Study 페이지에서 검색 결과를 클릭하는 경우에도 동일한 페이지 전환 및 콘텐츠 이동 로직을 적용하여 두 검색 기능의 동작 방식 통일
- 검색 결과 클릭 또는 `ESC` 키 입력 시 검색어와 검색 결과를 초기화하도록 구현
- 기존 검색창의 중복된 내부 박스 스타일을 정리하여 Home과 Study 페이지의 검색창 디자인이 일관되도록 개선

기존에는 Study 페이지 내부에서만 검색이 가능했지만, 이번 개선을 통해 Home 화면에서도 전체 학습 노트를 바로 검색할 수 있도록 변경했습니다. 특히 CLF-C02 기본 학습 내용과 SAA-C03 관련 심화 학습 내용을 하나의 검색 대상으로 통합하여 사용자가 별도의 도메인 선택 과정 없이 원하는 AWS 개념을 찾을 수 있도록 구성했습니다.

또한 검색 결과를 클릭하면 해당 콘텐츠가 속한 도메인이나 Advanced Topics 화면으로 자동 전환되도록 기존 페이지 전환 및 도메인 필터링 기능과 연동했습니다. 이를 통해 검색 기능이 단순히 관련 내용을 찾아 보여주는 역할에 그치지 않고, 사용자가 원하는 학습 콘텐츠로 직접 이동할 수 있는 탐색 기능으로 확장되었습니다. 특히 기존에 HTML의 `data-domain`과 `data-level` 속성으로 관리하던 학습 콘텐츠의 분류 정보를 JavaScript 검색 기능에서도 활용함으로써, 향후 새로운 학습 콘텐츠가 추가되더라도 해당 속성을 지정하면 통합 검색에 자연스럽게 반영될 수 있도록 구현했습니다.

### INFRA. Deployment Automation — GitHub Actions 배포 자동화

Phase 8까지는 파일을 수정할 때마다 AWS 콘솔에서 S3에 직접 업로드하고 CloudFront 캐시를 갱신해야 했습니다. 또한 GitHub에는 코드를 복사해서 올려 두는 방식이라, GitHub의 내용과 실제 서비스 중인 파일이 어긋날 수 있었습니다. 업로드 누락이나 캐시 갱신을 잊는 실수 가능성도 있었습니다.

이를 해결하기 위해 사이트 소스를 GitHub로 일원화하고, 배포 과정을 GitHub Actions로 자동화했습니다.

**주요 구현 내용**

- 사이트 소스를 저장소의 `site/` 폴더에 S3와 동일한 구조로 관리
- `main` 브랜치에 `site/` 변경이 push되면 실행되는 GitHub Actions 워크플로 작성
- `aws s3 sync --delete`로 S3의 내용을 `site/`와 일치시키고, CloudFront Invalidation으로 캐시 갱신
- GitHub OIDC를 사용해 임시 자격 증명을 발급받도록 구성하여 장기 액세스 키를 사용하지 않음
- IAM 역할은 해당 버킷의 목록 조회·업로드·삭제와 해당 배포의 캐시 무효화 권한만 부여
- 신뢰 정책으로 이 저장소의 `main` 브랜치에서 실행된 워크플로만 역할을 맡을 수 있도록 제한
- 버킷 이름, 배포 ID, 역할 정보는 GitHub Secrets로 분리
- 첫 적용 때 `--dryrun`으로 삭제 대상이 없는지 확인한 뒤 실제 배포로 전환
- `site/` 변경이 없는 push(README 수정 등)에서는 배포가 실행되지 않도록 경로 조건 설정

**Trouble Shooting: OIDC 역할 맡기 실패**

- **증상:** `Not authorized to perform sts:AssumeRoleWithWebIdentity` 오류
- **원인:** 신뢰 정책의 `sub` 조건을 `repo:소유자/저장소:ref:refs/heads/main` 형식으로 작성했으나, GitHub가 실제로 보내는 값에는 소유자와 저장소의 숫자 ID가 포함된 형식이었음
- **해결:** 워크플로에 임시 디버그 단계를 추가해 실제 토큰의 `sub`, `aud` 값을 출력하고, 그 값으로 신뢰 정책을 수정한 뒤 디버그 단계를 제거
- **배운 점:** 예시나 문서의 형식을 그대로 믿지 않고, 실제로 전달되는 값을 직접 확인하는 것이 빠른 해결로 이어졌음

이를 통해 파일 수정 후 `git push` 한 번으로 서비스에 반영되며, 배포 이력은 Actions 로그로 남습니다. 이전 커밋으로 되돌려 push하면 이전 버전으로 복구할 수도 있습니다.

## 5. AWS Deployment

프로젝트를 로컬 환경에서만 확인하는 것이 아니라, AWS 서비스를 활용하여 실제 웹 브라우저에서 접근할 수 있도록 배포했습니다.

### Amazon S3
- 정적 웹 사이트 파일 저장
- HTML, CSS, JavaScript 파일 관리
- CloudFront의 Origin으로 활용
- Block Public Access를 활성화하여 S3 객체에 대한 직접적인 퍼블릭 접근 차단
- Bucket Policy를 통해 CloudFront OAC의 접근만 허용

### Amazon CloudFront
- S3 버킷을 Origin으로 설정
- Origin Access Control(OAC)을 적용하여 CloudFront를 통한 안전한 S3 접근 구성
- AWS Edge Location의 캐싱을 활용한 콘텐츠 전달(지연 시간 최소화, 빠른 컨텐츠 전달)
- 배포 시 Invalidation을 자동 실행하여 캐시 갱신

### Deployment Process

**현재 방식 (자동 배포)**

1. 로컬 저장소의 `site/` 폴더에서 파일 수정
2. `git add site` → `git commit` → `git push`
3. GitHub Actions가 OIDC로 IAM 역할을 맡아 임시 자격 증명 발급
4. `aws s3 sync --delete`로 S3와 `site/` 내용 동기화
5. CloudFront Invalidation으로 캐시 갱신
6. 수 분 내 사이트에 반영

**초기 방식 (Phase 1~8)**

콘솔에서 S3에 파일을 직접 업로드하고 CloudFront Invalidation을 수동으로 실행했습니다. 이 방식의 한계(GitHub와 S3 불일치, 작업 누락 가능성)를 해결하기 위해 **자동화로 전환**했습니다.

### GitHub Actions & IAM

- GitHub OIDC 공급자를 IAM에 등록하고, 이 저장소의 `main` 브랜치에서 실행된 워크플로만 맡을 수 있는 역할 구성
- 장기 액세스 키 없이 실행 시마다 임시 자격 증명 사용
- 역할 권한: 해당 버킷의 `ListBucket`, `PutObject`, `DeleteObject`와 해당 배포의 `CreateInvalidation`
